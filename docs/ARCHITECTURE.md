# GYMFORGE — архитектура (Этап 1)

## 1. Цель и ценность
Персональный тренер в кармане: приложение говорит, что делать сегодня, с каким весом, и объясняет, почему вес меняется.
Ценность — решение «какой вес взять» и запись подхода за одно нажатие.

## 2. MVP (без чего приложение не работает)
1. Онбординг-профиль → персональная программа.
2. Программа: дни, упражнения, подходы/повторения/отдых, редактирование, замена.
3. Каталог упражнений с техникой.
4. Калькулятор веса (способы A–D, 1RM по Эпли).
5. Режим тренировки: подход одним нажатием, таймер отдыха, ±вес, замена/пропуск.
6. История + прогресс (графики, PR, объём).
7. Рекомендация прогрессии с объяснением.
8. Сохранение (localStorage; Supabase — опционально).

## 3. Сущности
Profile, Settings, Exercise (статический каталог), Program → ProgramDay → PlannedExercise,
WorkoutSession → LoggedSet, WeightRecommendation (запись изменения рабочего веса), BodyMeasurement.
Типы: `src/lib/types.ts`, валидация: `src/lib/schemas.ts` (Zod). SQL: `supabase/schema.sql`.

## 4. Жизненный цикл состояний
- Загрузка: skeleton, пока стор читает localStorage / Supabase.
- Пусто: нет профиля → онбординг; нет программы → генератор; нет истории → пустые состояния с действием.
- Ошибка: ошибки валидации у полей; повреждённые данные → сброс с подтверждением; ошибка сети Supabase → работа локально.
- Успех: запись подхода сразу в стор (автосохранение), завершение тренировки → сводка и рекомендации.
- Опасные действия (удаление программы, сброс данных, пропуск) требуют подтверждения.

## 5. Слои
`lib/` — чистая логика без React (тесты). `store/` — состояние + персистентность. `components/`, `pages/` — UI.

## 6. Декомпозиция (каждая ≤ 1–2 ч)
1. Токены и каркас навигации. 2. Типы + схемы. 3. Каталог данных. 4. calc + тесты. 5. Генератор программ + тесты.
6. Стор + persistence. 7. Онбординг. 8. Главная. 9. Программа/редактор. 10. Каталог UI. 11. Workout Mode.
12. Прогресс. 13. Профиль/настройки. 14. Supabase SQL + инструкция. 15. Проверка сценариев 1–12.
